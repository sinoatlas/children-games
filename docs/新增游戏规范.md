# 新增游戏规范

这个仓库保存今后设计的所有儿童游戏。先看`catalog.json`确定下一个编号；现有001和002，下一款是003。

## 一款游戏一个固定目录

目录名为`games/003-英文短名/`，标题写中文，目录名不带版本。沿用以下分类：

| 文件或目录 | 放什么 |
|---|---|
| README.md | 游戏对象、角色、时长、首局步骤、最少打印页码、下载链接 |
| game.json | 固定编号、中文标题、版本、适用对象、主题、材料路径和页数 |
| printable/ | 最终规则书和完整打印材料PDF |
| editable/ | 可修改规则、卡片文字、结构化卡片数据 |
| assets/ | 插画、图标等完整原素材 |
| src/ | 生成材料的代码与必要源文件 |
| references/ | 诗文或科学来源、图画提示词、版本说明 |
| downloads/003-英文短名/ | 对应完整ZIP（放在仓库根downloads下） |

图像原稿只保存一份。通过ZIP提供可直接使用的一套文件，ZIP里的开始说明要与该版本一致。

## 新增流程

1. 从`templates/`复制游戏说明与信息模板，填写真实内容；新游戏不要覆盖现有001、002。
2. 完成规则、图卡和全部可打印材料。记录角色分工、首局操作和可暂停方式。
3. 对引用的诗文、知识点核对来源；分别标明原文、节选和自编内容。保存插画原图和实际生成提示词。
4. 按PDF技能渲染并逐页检查；核对页数、卡片编号和首局材料是否齐全。
5. 填好`game.json`，在`catalog.json`添加该游戏，并更新根README目录表。
6. 用`python scripts/package_game.py 游戏编号`更新下载包，再运行`python scripts/check_library.py`。
7. 更新`SHA256SUMS.txt`后提交到本仓库；上传后核对远程文件与下载包。

## 更新现有游戏

沿用原编号、原目录，更新`game.json`和`catalog.json`中的版本；重生成后更新PDF、源稿、图片、ZIP和说明。首局页码改变时，修改游戏README与根README中的打印建议。需要历史版本时依靠Git提交历史，不复制整份“最终版、最终版2”目录。

## 生成器配置

`scripts/build_game.py`会把`src/`和素材复制到临时目录，运行`builder.entry`，再按`builder.outputs`把结果放回各用途目录。当前两款保留原生成器；新生成器可沿用配置，也可在本游戏README说明自己的生成方式。

ZIP包装脚本按配置恢复原套装名称和文件名，让已有开始说明与源脚本继续可用。没有旧式生成器的新游戏，ZIP直接包含游戏目录内容。
